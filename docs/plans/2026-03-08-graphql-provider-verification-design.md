# GraphQL Provider Verification Design (Apollo v4)

## Goal

Add a realistic provider-side verification example using a live Apollo v4 GraphQL server and Pact JS Verifier. The test should verify a pact generated by the consumer example end-to-end, exercising the plugin verification hooks.

## Scope

### Provider Server

- Express + `@apollo/server` v4 serving `/graphql`.
- Schema loaded from `examples/js/product-consumer/schema.graphql`.
- Resolvers return deterministic in-memory data that satisfies the consumer pact queries and mutations.
- Subscriptions are defined in the schema but not executed (no WebSocket transport).

### Verification Runner

- A standalone script that:
  1) starts the provider server on an ephemeral port,
  2) runs Pact JS `Verifier` using the pact file produced by `npm test`,
  3) shuts down cleanly.
- Sets `PACT_GRAPHQL_PLUGIN_VERSION=0.1.0` to ensure the plugin is loaded during verification.

### Scripts

- Add a `verify` script in `examples/js/product-consumer/package.json` to run provider verification separately from `npm test`.

## Data Flow

1) `npm test` generates pact files in `examples/js/product-consumer/pacts`.
2) `npm run verify` starts the Apollo server and runs `Verifier.verifyProvider()` against the pact file.
3) Pact Core calls plugin verification hooks to compare canonical vs runtime request payloads.

## Success Criteria

- `npm test` still generates pact files.
- `npm run verify` passes against the Apollo provider.
- Provider verification uses the same schema and produces realistic responses (no canned mismatches).
